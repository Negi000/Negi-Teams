# 登録した保存先から通常起動する

2026-10-03。Phase 0–8、NT-001–073の範囲を維持する。初回設定と保存状態のMaterial 3画面を、通常の統括チャット・Task受付へ接続する。

## 起動の選択

`NEGI_STORAGE_MODE=indexed` はサーバーを起動する人の明示設定である。HTTP、Task catalog、モデルのtool引数、ブラウザー保存から選ばない。未指定または`legacy`は従来の互換性検査を使い、登録済みの索引や初回準備のmarkerがあれば開始を保留する。不明な値は起動を保留し、従来方式へ切り戻さない。

今回のindexed通常起動は、`NEGI_SETUP_ROOT`で保存済みのプロジェクト設定を持つワークスペースを対象にする。設定が固定する`negi-master`、Codex、モデル/effort、checkoutと共有schedulerを使用する。別のlegacy catalogや固定agentを併用しない。複数プロジェクトの保存済み設定は同じTask受付を使う。任意のMaster/CLI/PTy配置をこの登録に自動移行するものではない。

## 画面から進める順序

1. `/setup`でプロジェクトと担当条件を保存する。
2. 同じ保存先へ書く旧サーバー・外部ツールを停止する。
3. 同じ設定と認証tokenで`NEGI_STORAGE_MAINTENANCE=1`のサーバーを起動する。
4. `/storage`で「初回の保存先」「会話の保存記録」「実行の保存記録」を確認して明示保存する。既存保存先では必要な登録を確認する。
5. 「保存の登録が完了しました」の管理者向け手順を確認し、メンテナンス用サーバーを終了する。
6. `NEGI_SETUP_ROOT`と認証tokenを保持し、メンテナンス設定を解除して`NEGI_STORAGE_MODE=indexed`で起動する。
7. 保存・担当モデル・ログイン・起動条件の確認後、`/storage`の「作業一覧へ」からTaskと統括チャットへ進む。

保存確認画面はサーバーの再起動やprovider処理を開始しない。登録済みであることと、担当の起動が確認できたことを別に表示する。通常起動は状態の確認だけを許可し、初回作成・baseline採用・復旧を行わない。通信失敗時は次の操作の案内を隠し、状態を再取得してから表示する。

## 実行と保留

Task stateを開く前に、固定されたroot/key/bootstrap、会話・実行の索引とMasterの起動時状態を検査する。未完了の保存、未解決の会話、残存owner、不一致は保持して開始を保留する。Task、統括の受付、統合実行は同じ登録のschedulerを使用する。モデル/ログインの確認失敗や設定版の変更でも新規開始を保留する。

indexedでは動的PTY追加と独立したsupervisor要約をサーバーで拒否し、画面の追加・要約操作も出さない。モデルへは登録済みTask操作だけを渡す。stopと診断は既存の明示操作を保持する。起動・再接続・読取によって保存済みturnを再送しない。

中断したTaskの照合は、そのTaskに残る実行枠を使用し、新しいthread/turnを開始しない。同一Taskのinspect/closeを`reconciliation.lock`で直列化し、provider読取とGit確認の間はroot全体の保存guardを保持しない。schedulerの読取・追加は登録済みwriter自身のguardを使う。provider読取の前後で固定した事実を再確認し、変化した観測を保存しない。クラッシュで残るlockをPIDだけで自動解除しない。checkoutの外部編集をOSで禁止する保証はない。

## 検証と残る条件

Windowsの実ファイル・native helperと、実サーバー/子プロセスが話す合成providerプロトコルを使用する。実モデルの成果品質、provider全体の終了、外部broker、実機safe-area/仮想キーボード、人の操作性の受入は別の条件である。

全Masterの移行、Codexの新しい会話、未知の処理・残存lockのGUI復旧、10,000件規模の性能、Jev/Policyの日本語校正と人の承認など、[実装状況](negi-teams-implementation-status.md)の残条件は継続する。この通常起動の接続はPhase 0–8全体の完成を意味しない。

# 統括から登録Taskを委任する

2026-10-01。明示設定したCodex chat Masterが、Task画面と同じ固定カタログ・`LocalTaskService`・単一schedulerを使用する接続。

## 起動と操作

既存のCodex Masterのopt-in設定と、起動時の`NEGI_TASK_CONFIG`を使用する。モデル・effort・Codex実行ファイルは明示設定を維持する。通常の統括起動はChatGPT認証を確認してからモデルのthreadを開き、APIキーを子プロセスへ渡さない。CLIの変更は新しい起動設定で確認し、過去のrun設定は書き換えない。

| 操作 | 入力 | 結果 |
|---|---|---|
| `negi_list_tasks` | 任意のproject・offset | 10件ずつの固定カタログ、契約ID・版・設定hash |
| `negi_read_task` | 登録済みrun ID | 完全な固定Task Contract、担当、検証・人間受入・現在の状態 |
| `negi_dispatch_task` | run ID・カタログのconfig hash | Task画面と同じschedulerへの一度だけの開始要求 |

チャットでは「Task一覧を取得」「Task契約を確認」「Taskを委任」と表示する。展開すると操作の識別子と入出力を確認できる。Task画面は利用者の開始と統括からの委任を区別する。古い起動元未記録のrunを利用者操作と推定しない。

## 固定する境界

- serverが登録した3操作だけをproviderへ渡す。workerには渡さない。
- thread・turn・call IDを照合する。同じcallの再送は同じ結果を返し、異なる引数でのcall ID再利用は拒否する。
- 起動要求は会話IDへ結び付けて永続化する。UIとの同時開始やサーバ再起動でも同じTaskを再実行しない。
- 契約・担当モデル・コマンド・checkout・承認・成果受入をモデル入力から変更しない。
- 完全な契約を返せない大きさのTaskは委任前に停止する。切断や結果不明時はTask画面で照合し、自動再試行しない。
- 統括の委任記録は人間の署名付き操作承認・成果受入とは別の記録である。

## 通常チャットの実行枠

Codex chat Masterは`NEGI_TASK_CONFIG`の同じschedulerを使う。稼働中のturnをAstraの読取作業として登録し、枠と作業場所の読取権を確保してから`turn/start`を送る。起動済みで待機しているプロセスは実行枠を占有しない。子プロセスの隠れた委任は引き続き無効。

入力・モデル・effort・会話ID、provider turn ID、終了応答とhashを、モデルの作業場所の外に保存する。Task状態の保存場所が統括の作業場所の中にある設定は未送信として拒否する。既存schedulerの並列数を保ち、API予算との混用を拒否する。未設定時の保守的な既定は従来と同じ1枠であり、planner 1＋worker 2の役割別設定を今回の接続だけで実装済みとは扱わない。

- 満席または作業場所の競合ならproviderへ送らず、今回の要求を未送信として取消記録する。入力と引用を保持し、空きができた後に利用者が再送できる。
- 確認できた終了・失敗・中断は証拠保存後に枠を解放する。解放時は同じサービスの待機Taskを再評価する。
- 切断・時間切れ・終了証拠の保存失敗は枠を保持する。自動再送・自動復帰せず、会話IDとturn IDを照合する。
- schedulerのMaster `verified`はprovider終了応答の確認を示す。Task品質の検証や人間の成果受入を示さず、金額は不明のまま。

Material 3のチャットは受付応答を待ってから入力を消す。要求IDが一致する応答または復元された会話だけで受付を確定し、他の送信と混同しない。送信結果の分からない切断では入力を保持し、自動再送しない。未送信の案内は共通のエラー色・14px本文・読上げ通知を使う。

## 確認と残る範囲

現在のCLI 0.159.2の生成したexperimental schemaを確認し、通常サーバのMaterial 3チャットから実Astraによる一覧・固定契約の読取を観測した。既存Task・Vaultの参照ノート・二つのcheckoutは前後で変化しなかった。実Taskの開始・停止・許可・受入はこの接続確認では行っていない。

合成Taskでは委任・重複・UIとの競合・再起動・契約hash不一致・大きな契約の拒否・人間受入の未生成を確認した。Chromiumの1440px/320px/375pxでチャット結果の展開、起動元、レビュー待ち、48px角の停止ボタンを確認した。実機のsafe areaと仮想キーボードは未確認。

追加の共通枠接続では、実Astra lowの読取1 turnが同じschedulerに記録され、終了証拠の保存と枠解放まで進むことを確認した。固定Task・Vault参照ノート・二つのcheckoutの前後比較に変化はなく、開始要求・人間受入は生成しなかった。この比較は全てのprovider内蔵操作の網羅的な監査ではない。合成providerでは満席・同時送信・停止・切断・証拠保存失敗・待機Taskの一度だけの再開を確認し、関連87件、型検査、ビルドが成功。Chromiumの1440px/320px/375pxとダークテーマで、拒否時の入力保持・受付後の消去・切断後の送信停止を確認した。全件の回帰試験と実機は別の未完了ゲート。

未登録の自由な依頼から新規Task Contractを確定する導線、旧MCP/PTY委任の全面移行、Task内のAstra計画を含むplanner/worker別容量の設定、統括のprovider照合と手動再開の画面、統括への完了通知は残る。この登録Task接続を全通常dispatchの移行完了とは扱わない。
